# G3-02 — retained IdP hardening

Status: implementation draft; separate merge authorization required. #517/#541, ADR-0087; baseline 1dc55509868c89ebb6fd6016c3659d0ae5a0d302. G3-02 preserves existing protocol, signer, session and wire profile. Two bounded correctness gaps: token redemption previously let client lookup and code-store exceptions escape the protocol error boundary; translate outage to temporarily_unavailable, never sign or restore an uncertain consumed code, do not consume before trusted tenant resolution. Signing previously checked only current key publication, while JWKS rejected duplicate retained IDs; centralize full verification-set validation for signing/discovery/JWKS, including supported RSA algorithms, unique key IDs and current key match. Preserve existing failure/rotation semantics; no new token type, key custody, grant, dependency or migration. Tests: fault injection, existing actual JDBC 20-way redemption and 11 negative burn paths (adapted A-only from #546), MVC current profile, RSA256/384/512 and retained overlap/duplicate rejection. Actual V42 shared disposable database and existing core/security tests; standalone MVC not full deployed filter chain. Independent QA/security, full filter-chain and fresh boot/seal evidence to reconcile before merge. No public deployment, no customer data.
