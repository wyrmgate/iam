## E1 — Kernel compatibility and transaction equivalence (#41, #541)

Owner: Kernel engineer for shared code; IAM Backend owns IAM adapter; Storage engineer owns consumer checks. Architecture/Security/QA review. Prerequisite: approved experiment execution; context semantics draft ADR-0085/0086 reviewed. Two sequential subexperiments, not a forced JDBC conversion.

E1a (core): compare existing context/IDs/errors/correlation with 0.3.2 using isolated consumer adapters. Resolve exact Maven artifacts, dependency tree, strict checksum, JDK21 and 25; test trusted projection from verifier, wrong issuer/same sub, tenant spoof, explicit DEPLOYMENT not TENANTLESS, reauthorization, no untrusted claim role mapping. Existing architecture boundary test and current Storage suite must pass. Measure duplicate code removed vs new adapter size (changed lines and maintained classes, not mandatory arbitrary threshold); report dependency/CVE/license impact. Stop if context weakens isolation; retain existing mechanism and propose minimal generic port. No library version upgrade without actual conformance.

E1b (JDBC): compare current IAM JdbcIdempotencyRepository/JdbcOutboxRepository with Kernel JdbcReliabilityTransaction and fenced outbox on isolated PostgreSQL using one synthetic authoritative mutation. Map scope, fingerprint, revision, event/evidence intent, caller checks and lease/retry semantics. Run rollback after mutation/intent/result; 20 concurrent same-key requests -> one effect; different fingerprint -> conflict; tenant T2 same key isolated; lost response/retry -> same authorized outcome; revoked replay denied; stale lease fenced; crash before/after commit/publish; restore/replay duplicates -> no double effect; no external network inside commit. Assert atomic business+required intents+replay result, audit ownership untouched, no double authoritative store. Test current Storage durable contracts separately; compare p95 under same fixture and bounded contention, no arbitrary performance guarantee. If any invariant fails, reject JDBC replacement for now; E1a may pass independently. Output exact-version consumer build, compatibility matrix, recommended retained/adapted mechanisms and candidate release gate. No published release until approved.
