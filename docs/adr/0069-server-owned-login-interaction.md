# ADR-0069: Server-owned local login routing and authorization interaction

Status: Accepted

## Decision

Catalog SSO registration has an optional typed authenticationTargetId, referencing an ACTIVE ApplicationTarget in the same Tenant with an ACTIVE parent Application. This is the local credential account realm, not necessarily the relying-party application target. Catalog validates it on create/replace and protocol use. Existing registrations without a binding can reuse a valid browser session but cannot start local interactive login. The installation Console registration is seeded from the exact durable installation plan and new bootstrap creates the binding. No browser-supplied target or tenant is authoritative. Console direct login uses only its sealed registration and its bound target; remove public client/target login inputs.

The authorize endpoint validates the complete request (client, exact redirect, response type, scope, state, nonce, S256, prompt) before creating an interaction. With a valid session, default/none may issue a code; none without a session returns login_required, never a page. login always requires new proof; unsupported prompt combinations and max_age are rejected rather than ignored. An interaction is Platform technical state, five-minute expiry, one use, exact registration ID/revision/tenant and original request binding. An HttpOnly Secure SameSite=Strict host-only browser cookie and distinct hidden form nonce bind the continuation; persist only digests. GET renders a no-store, frame-denied same-origin HTML form, no external scripts or third-party assets; POST consumes the interaction atomically before verifying credentials, revalidates client and target, then issues through the existing protocol service. Invalid proof ends the attempt without issuing a code. Client change/retirement or expired/replayed/wrong-browser interaction fails closed; never redirect to a newly untrusted URI. Successful reauthentication revokes the previous browser session, sets the normal session/CSRF cookies and redirects only to the original registered URI. Multiple simultaneous tabs may supersede a prior interaction cookie; restart authorization. No consent or account selection engine.

The same credential verification service serves Console and protocol login. No duplicate User, Credential, access authority or external provider network call. Retain external bearer mode and installation recovery; they are not superseded. V32 introduces the Catalog binding and typed interaction table. Runtime cleanup is a separate bounded technical operation, not Audit evidence deletion.
